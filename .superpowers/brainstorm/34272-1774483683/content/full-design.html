Full design: district breakdown

Three layers — API, types, and UI. Review each section and confirm before we write the spec.

1 · API route change

Add one new aggregation to app/api/public/water-use-dashboard/route.ts. The existing district field is already on every system permit record (from a.district in the SQL join). We just need to count them, grouped by province.

// Added to snapshot response
permitsByDistrict: Array<{
province: string;
districts: Array<{
key: string;
label: string;
count: number;
percentage: number; // % of province total, not national
}>;
}>
Key decision: District percentages are relative to their province total — e.g. "Nyagatare = 29% of Eastern Province". This is more meaningful than the national share.
Note: Registry permits have no district field — only system permits. The same skip-if-empty logic used for province applies here. Districts with empty values are excluded.

3 · Interaction details

Chevron icon — rotates 90° right→down on expand (CSS transition, 150ms ease-out). Uses ChevronRight from lucide-react, same icon set already used.
District bar color — lighter emerald (bg-emerald-200) to visually subordinate them under the province-level bars (bg-emerald-600/400/300). Top 3 districts brighter, rest dimmer.
Small label — "Districts — % of province total" in uppercase 10px muted text at top of expanded section, so users understand the percentage denominator.
Empty state — if a province has no districts with data, show "No district data available" instead of an empty expansion. Province row still clickable.
Mobile — district name gets min-w-0 truncate, count/percentage are right-aligned and shrink-0. Bar fills remaining space with flex-1.
