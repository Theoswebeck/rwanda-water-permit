# Unify Permit PDF Generation on PDFKit — Design Spec

**Date:** 2026-04-21
**Project:** Rwanda Water Permit System (waterpermit)
**Status:** Approved

---

## Problem

The codebase appears to contain two parallel PDF generators for water permits:

- `lib/pdf-permit-server.ts` — PDFKit, server-only (876 lines)
- `lib/pdf-generator.ts` — jsPDF, browser + server (2,552 lines)

The staff preview endpoint renders permits via PDFKit. The intent was that the jsPDF generator rendered the *issued* PDF. This created a perceived risk that "preview PDF" and "issued PDF" could drift visually or in content — meaning what staff see during review would not match what the applicant receives.

### Discovery during design

A full callsite audit revealed that **the jsPDF permit-rendering code is dead code**:

- `generateDigitalWaterPermit` and `generateDigitalWaterPermitBlob` (lib/pdf-generator.ts:1444, :1463) are exported but never imported anywhere in the application.
- The only external imports from `pdf-generator.ts` are `generateTermsConditionsPdfBlob` (terms & conditions PDF) and `generateFieldReportPdf` (inspection field report) — neither is a permit.
- The approver final-decision route (`app/api/approver/final-decision/route.ts`) does not generate any PDF; it transitions the application to `approved_pending_permit` status and sends notifications.
- The transfer issue route (`app/api/transfers/issue/route.ts`) does not generate any PDF; it updates ownership on an existing permit row.

**All permit PDFs that end users actually see are generated by `generatePermitPdfBuffer` in `lib/pdf-permit-server.ts`**, called from three routes:

| Route | Purpose | `skipQr` |
|-------|---------|----------|
| `/api/staff/applications/[id]/permit-preview` | Staff preview tab | `true` → DRAFT banner + watermark |
| `/api/public/permits/pdf/[...permitNumber]` | Applicant download of issued permit | `false` → QR footer |
| `/api/test/permit-pdf` | Test harness | variable |

**Preview and issued already come from the same function.** They differ only by the `skipQr` flag.

### Actual remaining problems

1. **Dead code** (~1,800 lines) in `pdf-generator.ts` invites future editors to modify the wrong file, believing it is live.
2. **Kinyarwanda page gap.** The jsPDF code at `pdf-generator.ts:1196` renders a full Kinyarwanda translation page for `abstraction_organization` permits. PDFKit has no Kinyarwanda. Because PDFKit is what users actually see, no issued permit today has a Kinyarwanda page.
3. **Iframe error handling missing.** All four staff preview pages render the permit in an `<iframe>` without an `onError` handler. When the preview endpoint returns an HTTP error, the loading spinner hangs forever.
4. **Renewal leap-year off-by-one.** `resolvePermitDuration()`'s `setFullYear` math drifts by one day when the issue date is Feb 29 of a leap year — the computed expiry lands on Mar 1 instead of Feb 28.
5. **No end-to-end parity verification** across the 16 scenarios (4 variants × 4 application types).

---

## Goals

- Establish `lib/pdf-permit-server.ts` (PDFKit) as the single canonical permit renderer. Remove any ambiguity about where permit rendering lives.
- Ensure the PDF a staff reviewer sees in the preview tab is **visually identical** to the PDF the applicant receives — same layout, same text, same values — minus the intentional DRAFT banner+watermark vs. QR footer difference.
- Port the Kinyarwanda page for `abstraction_organization` permits from jsPDF into PDFKit so issued org-abstraction permits carry Kinyarwanda translation.
- Fix the leap-year renewal bug.
- Fix the hanging-spinner iframe failure mode.
- Verify all 16 scenarios render correctly end to end.

## Non-Goals

- **Kinyarwanda for the other 3 variants** (abstraction_individual, concession_individual, concession_organization). Tracked by the existing `docs/superpowers/specs/2026-03-29-kinyarwanda-translation-completion-design.md` spec; out of scope here.
- **Per-application access control on the preview route.** Current behavior (any of `admin`/`reviewer`/`approver`/`verifier`/`inspector`/`assessor` can preview any application) is kept and documented as intentional — the preview URL is internal-only and not exposed to applicants.
- **Backfill of previously-issued permit PDFs.** Not applicable: no permits have been issued in production. UAT permits are disposable.
- **Changes to `generateTermsConditionsPdfBlob` or `generateFieldReportPdf`** — they stay in `pdf-generator.ts` and are unaffected.

## Design

### Architecture

**Target state:**

```
┌──────────────────────────────────┐   ┌──────────────────────────────┐
│  lib/pdf-permit-server.ts        │   │  lib/pdf-generator.ts        │
│  PDFKit                          │   │  jsPDF (~700 lines after     │
│  + Kinyarwanda page              │   │         deletions)           │
│    (abstraction_organization)    │   │                              │
│  + leap-year-safe date math      │   │  Exports ONLY:               │
│                                  │   │    • generateTermsConditions │
│  The canonical permit renderer.  │   │        PdfBlob               │
└──────────────┬───────────────────┘   │    • generateFieldReportPdf  │
               │                       └────────┬─────────────────────┘
               │                                │
   ┌───────────┼───────────┐             ┌──────┴────────┐
   ▼           ▼           ▼             ▼               ▼
 preview    public      test           terms         field
 route      permit      harness        preview       report
            route                      flow          flow
```

One generator for permits. The file containing jsPDF permit renderers shrinks to the two non-permit helpers that are still in use.

### Components

#### A. `lib/pdf-permit-server.ts`

**A.1 Add Kinyarwanda page for `abstraction_organization`.**

After `renderAbstractionOrganization()` finishes the English permit body, call a new `drawKinyarwandaOrgAbstractionPage()` helper that:
- Calls `doc.addPage()`.
- Renders the same fields (applicant/org name, permit number, water source, location, volumes, permit duration, validity dates) using Kinyarwanda labels and surrounding sentences, mirroring the jsPDF layout at `pdf-generator.ts:1114–1231`.
- Uses the validity sentence template: `"Uru ruhushya rufite agaciro kuva ${formatDateDMY(issue)} kugeza ${formatDateDMY(expiry)}."`
- Honors `skipQr`: when `true`, the Kinyarwanda page is overlaid with the same DRAFT watermark as page 1; when `false`, the QR footer is rendered on it too.
- Does **not** re-render the RWB letterhead — the Kinyarwanda page is a "translation appendix," not a standalone permit.

Copy for labels/headings is lifted verbatim from the existing jsPDF renderer to ensure continuity with the Kinyarwanda translation work already approved in prior specs.

**A.2 Fix leap-year date math.**

Replace the `setFullYear` pattern used in renderer expiry-date fallbacks:

```ts
// Before
const d = new Date(issueDate);
d.setFullYear(d.getFullYear() + years);
return d;
```

with a date-only helper that clamps to the last day of the target month:

```ts
function addYearsSafe(date: Date, years: number): Date {
  const y = date.getFullYear() + years;
  const m = date.getMonth();
  const d = date.getDate();
  // Feb 29 + N years → Feb 28 in non-leap target years
  const daysInTargetMonth = new Date(y, m + 1, 0).getDate();
  return new Date(y, m, Math.min(d, daysInTargetMonth));
}
```

Use `addYearsSafe` everywhere a validity expiry is computed from an issue date in `pdf-permit-server.ts`.

**A.3 No other library changes.** Access-control enforcement stays in the route, not the library.

#### B. `app/api/staff/applications/[id]/permit-preview/route.ts`

**B.1 Normalize error responses.** When the PDFKit render throws, return `application/json` with `{ success: false, message, status }` and an appropriate HTTP status. Never return a partial PDF. Never return a naked 500 body without the content-type set.

**B.2 No access-control changes.** Kept per Non-Goals above.

#### C. All four staff preview tabs

Files:
- `app/review/application/[id]/page.tsx`
- `app/assessment/.../page.tsx`
- `app/approver/.../page.tsx`
- `app/verification/.../page.tsx`

**C.1 Replace the bare `<iframe src="/api/...">` with a small client component that fetches and detects failures.** An iframe does not fire `onError` for HTTP 4xx/5xx; the browser still "loads" the error body, so the existing `onLoad` handler hides the spinner regardless. The fix:

Extract a `PermitPreviewFrame` component that:
1. `fetch`es the preview URL on mount.
2. On `res.ok`: converts the response to a `Blob`, creates a blob URL with `URL.createObjectURL`, and sets it as the iframe `src`.
3. On non-`ok`: parses the JSON error and renders an inline error card (not a spinner). Includes a retry button.
4. On network failure / JSON parse failure: renders a generic "could not generate preview" error state with retry.
5. Revokes the blob URL on unmount.

This component replaces the four ad-hoc iframe blocks, reducing duplication.

#### D. `lib/pdf-generator.ts` — dead-code removal

Delete the following exports and their internal helpers:

- `generateDigitalWaterPermit`
- `generateDigitalWaterPermitBlob`
- `renderAbstractionIndividualPermitPdfBlob`
- `renderAbstractionOrganizationPermitPdfBlob`
- `renderConcessionIndividualPermitPdfBlob`
- `renderConcessionOrganizationPermitPdfBlob`
- `computeValidityYearsFromDates`
- `resolveApplicantName` (jsPDF version)
- `resolveOrganizationNameForPermit`
- `resolveOrganizationRepresentative`
- `resolveOrganizationRegisteredOfficeAddress`
- `resolveApplicantIdNumber`
- `resolvePermitDurationYears`

Retain: `generateTermsConditionsPdfBlob`, `generateFieldReportPdf`, and any helpers those two functions transitively depend on (e.g., font loaders, `addFileToVFS` calls, date formatters *if shared*).

**Method:** after deleting the obvious blocks, run `tsc --noEmit` and let TypeScript identify any dangling references. If a helper is referenced only by deleted code, delete it too.

**Expected reduction:** ~1,800 lines. Target post-delete size: ~700 lines.

#### E. `app/api/test/permit-pdf/route.ts` — expand for verification matrix

Accept query parameters `?variant=<variant>&appType=<appType>` and synthesize a fixture `PermitApplication` object covering that scenario, then call `generatePermitPdfBuffer`. Variants: `abstraction_individual | abstraction_organization | concession_individual | concession_organization`. Application types: `standard | renewal | modification | transfer`.

Fixtures live inline in the route as `const FIXTURES: Record<string, PermitApplication> = {...}`. Each fixture exercises the resolvers — e.g., the `transfer` fixtures populate `internal_notes.transferFormData` with transferee data; the `modification` fixtures set `isModification: true`; the `renewal` fixtures include an `originalPermitNumber`.

This route is the backbone of the manual QA pass (§ Testing).

## Data Flow

Unchanged by design — both paths already hit the same function. The point of the change is to lock this in as the *only* path going forward.

```
Staff preview tab
  → GET /api/staff/applications/[id]/permit-preview
    → generatePermitPdfBuffer({ skipQr: true, ... })
      → PDFKit Buffer
    → iframe renders (via PermitPreviewFrame)

Applicant download
  → GET /api/public/permits/pdf/[permitNumber]
    → findPublicPermitByNumber (application context)
    → generatePermitPdfBuffer({ skipQr: false, ... })
      → PDFKit Buffer with QR footer
    → browser downloads
```

Both paths hit `generatePermitPdfBuffer`. The PDFs share identical fields, layout, and text; they differ only in the footer overlay (QR vs. DRAFT banner) and the per-page DRAFT watermark on the preview variant.

## Error Handling

| Surface | Failure mode | Behavior |
|---------|--------------|----------|
| Preview route | PDFKit render throws | Catch, log with traceId, return 500 + `{success:false, message}` as JSON with `Content-Type: application/json`. |
| Preview route | Application not found | 404 + JSON error. |
| Preview route | Application `internal_notes` unparseable | Log warning; attempt render with defaults; if renderer still fails, 500. |
| Public permit route | PDFKit render throws | Already handled at line 187. Verify no regression. |
| Preview iframe | HTTP 4xx/5xx | `PermitPreviewFrame` detects via `!res.ok`, shows inline error card with retry button. |
| Preview iframe | Network failure | Same error card, different message. |
| Preview iframe | Empty response body | Treat as failure, show error card. |

## Testing Strategy

### Unit tests

- **Leap-year:** Issue date `2024-02-29`, 5-year permit → expiry `2029-02-28` (not `2029-03-01`).
- **Leap-year edge cases:** `2024-02-29` + 4 years → `2028-02-29` (still leap); + 1 year → `2025-02-28`.
- **Validity sentence formatting:** `formatDateDMY` produces `DD/MM/YYYY` with leading zeros.
- **Transfer field resolution:** `resolveOrgRep`/`resolveApplicantName`/`resolveOrgAddress` correctly prefer `transferFormData.transferee*` over `notes.*` fallbacks.

### Integration / manual QA — the 16-scenario matrix

Run the expanded `/api/test/permit-pdf` route for each combination:

| Variant \ App type         | standard | renewal | modification | transfer |
|----------------------------|:--------:|:-------:|:------------:|:--------:|
| abstraction_individual     |    ✓     |    ✓    |      ✓       |    ✓     |
| abstraction_organization   |    ✓✓    |   ✓✓    |     ✓✓       |   ✓✓     |
| concession_individual      |    ✓     |    ✓    |      ✓       |    ✓     |
| concession_organization    |    ✓     |    ✓    |      ✓       |    ✓     |

`✓✓` = also verify the Kinyarwanda second page renders and contains matching dates/volumes/names.

For each cell, compare the `skipQr: true` output (preview-style) against the `skipQr: false` output (issued-style). They must be visually identical except for the DRAFT watermark + banner vs. QR footer.

### Regression guardrails

- PDFKit writes a creation timestamp into the PDF metadata, so two runs with identical inputs produce different bytes. Automated assertion therefore checks **structural equivalence**: matching page count, matching byte-length within ±2%, and extracted text contains all expected field values (applicant name, permit number, volumes, validity dates).

### Post-deployment smoke test (UAT)

1. Create a `standard`/`abstraction_organization` application, run it through approval.
2. Open the staff preview — confirm DRAFT banner, watermark, and Kinyarwanda page 2.
3. Accept terms, issue the permit, open the public download URL.
4. Diff visually (side-by-side): same fields, no DRAFT, has QR on the footer.

## Rollout

Single PR. Risk: low (no production permits, UAT is disposable). Suggested commit order within the PR for reviewability:

1. `lib/pdf-permit-server.ts` — add `addYearsSafe` + replace callsites.
2. `lib/pdf-permit-server.ts` — add `drawKinyarwandaOrgAbstractionPage` + wire into `renderAbstractionOrganization`.
3. `app/api/test/permit-pdf/route.ts` — expand fixtures.
4. New `components/staff/permit-preview-frame.tsx` + replace iframe usage in four preview pages.
5. `app/api/staff/applications/[id]/permit-preview/route.ts` — normalize error response.
6. `lib/pdf-generator.ts` — delete permit-rendering exports and now-unreferenced helpers. Run `tsc --noEmit` and `next build`.
7. Run the 16-scenario matrix; record results in the PR description.

Each step is independently testable. Steps 1–3 can ship without 4–6 and vice versa.
